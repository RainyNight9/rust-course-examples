P01 · 这本书该怎么读

全书导览 · 视频 10.44 分钟 · ep01.mp4

本集目标

  1. 看懂 Rust 的三个承诺 —— 内存安全、线程安全、零成本抽象分别解决什么问题
  2. 拿到全书的结构地图 —— 四段递进的内容，以及对应到哪几集
  3. 建立正确的学习心态 —— 把编译错误读成设计反馈，而不是失败

核心规则

  • 悬垂引用 —— 引用的数据已经离开作用域，指针还指着旧地址。
  • 二次释放 —— 同一块堆内存被释放两次，堆元数据被写坏。
  • 越界访问 —— 索引超出缓冲区长度，读到或写到别人的内存。
  • 迭代器失效 —— 遍历过程中改动容器，迭代器内部指针失效。
  • rustc --version —— 确认工具链装好，本系列基于 Rust 1.85 之后的 2024 Edition。
  • cargo new + cargo run —— 新建项目能打印 Hello, world!，说明编译与运行链路通了。
  • edition = "2024" —— 决定编译器按哪套惯用法检查，示例统一以此为准。
  • rustup doc —— 本地离线标准库文档，查 API 比搜索更可靠。

关键结论

  • 所有权管「归谁」类型系统管「能做什么」并发管「怎么流动」：第 4 章、第 5–10 章、第 16–17 章
  • 报错是编译器在提前指出潜在 bug，而且它通常连修改建议都写好了。：读错误码，不猜、先跑最小例子、别和借用检查器硬刚

容易踩的坑

  • 别的地方是：不需要垃圾回收器，却能在编译期保证内存安全。
  • 注意它防的不是「程序写错了」，而是一类很具体的运行时灾难：访问已经释放的内存、重复释放同一块内存、缓冲区越界、迭代器中途失效。
  • 别的语言里往往要等到线上才炸，Rust 让它们在编译期就过不了。
  • 注意这不是运行时抛异常，而是编译直接失败，错误码 E0382，还会告诉你值在哪里被移动过。
  • 别扭，但换个角度想：这类 bug 从此再也不会流到用户机器上。

随堂练习

题目：如果一段代码在别的语言里能跑、只是偶尔崩，Rust 拒绝编译它，这是语言的缺点还是设计取舍？

提示：提示：想想三个承诺里的第一个，以及它防住的是哪一类 bug。

答案讲解：是刻意的设计取舍。Rust 把「可能出问题」当成编译错误，代价是你要显式写出所有权和借用关系，换来的是这类 bug 不会流到运行时。所以看报错时该问的是「我的数据关系哪里没说清」，而不是「怎么让编译器闭嘴」。

知识地图

  1. 三个承诺（P01）—— 内存安全、线程安全、零成本抽象，是全书所有语法的出发点。
  2. 四段结构（P01–P22）—— 入门、基本技能、编程思想、高级主题，逐层复用所有权规则。
  3. 学习心态（贯穿全程）—— 把报错读成设计反馈，用最小例子定位，不硬绕过检查。

P02 · 装好环境，跑起第一行代码

第 1 章 入门指南 · 视频 8.24 分钟 · ep02.mp4

本集目标

  1. 拆开 rustup 工具链 —— 知道 rustc、Cargo、标准库文档分别是什么，会切换 channel
  2. 看懂 Cargo.toml 与依赖 —— 理解 edition、版本语义与 Cargo.lock 各自管什么
  3. 分清 dev 与 release —— 会用 check 和 clippy，知道优化在哪一步才生效

核心规则

  • 感叹号是标志 —— println! 是宏，写成 println 会报找不到函数。
  • 参数个数可变 —— 函数签名是固定的，宏能接任意多个格式化参数。
  • 编译期就校验 —— 占位符与参数类型不匹配，当场报 trait 或类型错误。
  • 别塞复杂逻辑 —— 宏参数可能被重排或展开多次，副作用要谨慎。

关键结论

  • 装工具链 → 建项目 → cargo run剩下的交给 Cargo。：rustup 管版本、Cargo 管项目、check 省时间

容易踩的坑

  • 别是什么，会切换 channel。
  • 容易错在漏查 Cargo 和文档，后面示例会卡在环境上，动手前分别确认一下最省事。
  • 容易错在stable 上编译实验特性，改用 cargo 加 nightly 切换。
  • 容易错在给没实现 Display 的类型用大括号，或占位符个数和参数对不上，都会当场报错。
  • 容易错在漏写感叹号报找不到函数；也别在参数里塞有副作用的表达式，展开后求值顺序未必如你所想。

随堂练习

题目：同事 clone 你的项目后，装到的依赖版本和你不一样，问题出在哪，怎么保证一致？

提示：想想清单里的版本范围和锁文件各自管什么，以及二进制项目该不该把锁文件提交进仓库。

答案讲解：清单里是兼容范围而非精确版本，Cargo 取范围内最新。真正定死的是 Cargo.lock，二进制项目应把它提交，团队按锁文件还原就一致。想升级用 cargo update，别手改锁文件。

知识地图

  1. rustup 工具链（P02）—— 编译器、Cargo、标准库文档是一整套，channel 决定用哪套语法特性。
  2. Cargo.toml 与 Cargo.lock（P14）—— 版本范围声明意图、锁文件锁定结果，是后面所有工程章节的基础。
  3. dev / release profile（贯穿全程）—— 编译期优化直接决定性能，测速必须用 release 构建。

P03 · 一个小游戏串起基础语法

第 2 章 猜数字游戏 · 视频 8.81 分钟 · ep03.mp4

本集目标

  1. 跑通完整猜数字游戏 —— 从读输入、生成随机数到循环退出，能独立写出最终版
  2. 读懂 &mut 与 Result —— 知道 read_line 和 parse 为什么返回 Result，怎么处理两个分支
  3. 会用 match 与类型转换 —— 理解 cmp 的类型前提、parse 的类型标注与遮蔽技巧

核心规则

  • & 只读借用 —— 只是借用，不取得所有权，可以同时有多个。
  • &mut 可变借用 —— 要改值就用它，同一时刻只允许有一个。
  • 三处都要 mut —— 变量声明、实参、形参签名必须同时对上。
  • 用完自动归还 —— 函数返回借用就结束，原变量照常可用。

关键结论

  • cmp(&secret) 要求同类型，还要都实现 Ord：guess: u32、secret: u32、返回 Ordering
  • 先跑通，再理解。这个小游戏就是后面所有概念的索引。：&mut 可变借用、match 穷尽分支、Result 两种结果

容易踩的坑

  • 容易错在把读进来的字符串和转完的数字当成同一个变量，其实靠遮蔽换了类型，秘密数也要标成 u32。
  • 容易错在忘了读整行会带进换行符，不去空白直接转数字必失败。
  • 容易错在以为 expect 是忽略错误，其实出错就崩。
  • 容易错在只写引用没写 mut，会报不能把不可变值借成可变。
  • 容易错在清单和锁文件版本对不上。

随堂练习

题目：玩家输入 abc 时，错误分支的 continue 做了什么？换成 break 会怎样？

提示：想清楚 parse 的两个结果分支，以及 continue、break 分别把控制流带到哪里。

答案讲解：parse 失败返回 Err，continue 跳回循环顶部重新读，这轮比较不执行也不崩。换成 break 就一输错就结束游戏，容错没了。两者控制同一层循环，只是去向不同。

知识地图

  1. &mut 与借用（P06）—— 读输入那三处 mut，是第 4 章引用规则给的第一印象。
  2. Result 与 match（P09）—— expect 和 match 两种处理，是第 9 章错误处理的雏形。
  3. 类型推断与遮蔽（贯穿全程）—— parse 需要类型标注、同名变量换类型，贯穿后面所有章节。

P04 · 变量、类型、函数、控制流

第 3 章 常见编程概念 · 视频 8.55 分钟 · ep04.mp4

本集目标

  1. 分清 mut 与遮蔽 —— 知道两者何时用、能否换类型、作用域差在哪
  2. 读懂语句与表达式 —— 理解分号如何决定返回值，理解 if 和块都是表达式
  3. 掌握标量与控制流 —— 会选整数类型、看清溢出行为，用 for 安全遍历

核心规则

  • 未使用的变量会警告 —— 声明了却没用，编译器提醒你可能漏了逻辑。
  • 写了 mut 却没改 —— 也会警告，说明这个 mut 是多余的。
  • 下划线前缀消警 —— 用下划线开头，明确表示故意不用。
  • 别滥用 allow —— 大面积屏蔽会把真问题一起藏起来。
  • char 用单引号 —— 'a'、'中' 都是合法的 char 字面量。
  • 字符串用双引号 —— “hello” 的类型是 &str，和 char 不是一回事。
  • char 占四个字节 —— 存的是 Unicode 标量值，不是单个字节。
  • 按字节切要小心 —— 中文跨多个字节，切在中间会 panic。

关键结论

  • if、块、match 都是表达式能直接给 let 赋值：分支类型要一致、分支别加分号、整门语言都这么组合
  • 默认不可变 · 类型写清楚 · 一切皆表达式：let / mut、签名即契约、分号有语义

容易踩的坑

  • 容易错在把变量不能改和绑定不能改混为一谈。
  • 别的语言过来最容易下意识重新赋值。
  • 容易错在为消警告到处加 allow，把有用信号一起屏蔽。
  • 容易错在遮蔽后还想用旧值，它已经访问不到了。
  • 容易错在以为内层改到了外层，或把块内变量拿到块外用，那已超出作用域。

随堂练习

题目：下面这个函数为什么编译不过，又该怎么改：fn f() -> i32 { 5; }

提示：回忆语句和表达式的区别，以及块最后一行带不带分号分别返回什么。

答案讲解：末尾分号把 5 变成语句，值是空元组，和签名里的 i32 对不上，报类型不匹配。去掉分号，5 就是表达式，作为返回值传出。可见 Rust 里分号有语义，不是可有可无的收尾符。

知识地图

  1. 默认不可变与遮蔽（P05）—— mut 改值、遮蔽换类型，是所有权与借用规则的前置习惯。
  2. 语句与表达式（P13）—— 分号决定返回值，是后面闭包、迭代器链的写法基础。
  3. 标量类型与控制流（贯穿全程）—— 整数溢出行为、for 安全遍历，贯穿之后所有章节。

  2. 看懂移动与报错 —— 能解释赋值为何让原变量失效，读懂 E0382

核心规则

  • 获取即初始化 —— 创建字符串的同时就完成了堆内存申请。
  • 离开作用域自动释放 —— 右花括号处调用 drop 归还内存。
  • 所有资源一视同仁 —— 文件、锁、连接都靠同一套作用域规则。
  • 别手动 forget —— 跳过 drop 通常就意味着内存泄漏。
  • 每一个值都有一个所有者 —— owner，通常就是绑定它的那个变量
  • 任一时刻有且只有一个所有者 —— 不允许两个变量同时拥有同一份堆数据
  • 所有者离开作用域，值将被丢弃 —— Rust 自动调用 drop 归还内存
  • 整数 / 浮点 / bool / char —— 全部实现 Copy，赋值后原值仍可用。

关键结论

  • 一个值 → 一个所有者 → 一个作用域所有报错都能推回来：唯一所有者、离开即释放、移动是推论

  • 容易错在以为要像 C 手动关闭。
  • 容易错在以为变量里装着字符串本身。
  • 容易错在以为赋值就是拷贝，结果两个变量指向同一块堆内存、离开作用域二次释放。
  • 容易错在把内部块的临时值拿到块外去用。

P06 · 引用、借用与 slice

第 4 章 所有权（下） · 视频 8.87 分钟 · ep06.mp4

本集目标

  1. 会用引用不交所有权 —— 看懂引用类型签名、借用什么时候算结束
  2. 记牢两条借用规则 —— 能解释 E0499、E0502，理解非词法生命周期

核心规则

  • 取地址创建引用 —— &s 得到指向 s 的引用，不复制堆数据。
  • 星号解引用 —— *r 拿到引用指向的值，多数方法会自动处理。
  • 引用不释放数据 —— 函数结束只结束借用，原值由所有者释放。
  • 借用也要标类型 —— 签名和实参的取地址符必须同时写对。
  • 一个可变引用 —— 同一时刻对同一数据只能有一个可变借用。
  • 与只读互斥 —— 存在可变借用时不能同时保留只读引用。
  • 单线程也适用 —— 规则不看有没有线程，一律检查。
  • 传一层仍是独占 —— 把可变引用再传给别的函数，独占性不变。

关键结论

  • 3 条所有权 + 2 条借用= 内存安全与无数据竞争：移动与 drop、借用不拥有、引用必须有效

容易踩的坑

  • 容易错在签名忘了写取地址符，结果还是按值传移走所有权。
  • 别扭：函数只想算个长度，却得把字符串原样带回来。
  • 容易错在以为函数拿到值就等于拿到所有权，或把引用传进需要所有权参数的函数。
  • 容易错在以为要手动加一堆星号，或在需要所有权处误传引用。
  • 容易错在以为必须加花括号缩作用域。

随堂练习

P11 · panic! 与 Result

第 9 章 错误处理 · 视频 8.26 分钟 · ep11.mp4

本集目标

  1. 分清两类错误 —— 知道什么时候该 panic!、什么时候把决定权交回调用方
  2. 把 Result 和 ? 用对 —— match 穷尽、Ok 包装、From 转换，以及典型报错
  3. 会调试与配置 —— RUST_BACKTRACE、should_panic 测试、panic = abort

核心规则

  • 默认 unwind 逐层清理 —— 会调用各层析构，可配 catch_unwind，产物稍大。
  • abort 直接终止进程 —— 不做清理、二进制更小，适合发布版。
  • panic 不是错误处理 —— 别用 panic 代替 Result，前者表示不该继续。
  • RUST_BACKTRACE 看调用栈 —— 定位崩溃最常用，全量信息设 full。
  • 示例、原型、测试 → 可以 unwrap / expect —— 重点是让代码短，不必写完整错误处理
  • 库代码 → 优先返回 Result —— 把重试、降级、提示的决定权留给调用方
  • 契约被破坏、状态不可能恢复 → panic! —— 比如传入了明显非法的不变量，继续运行只会产生更隐蔽的错误

关键结论

  • 错误是返回值，不是异常。签名写清楚，编译器替你盯着。：panic! 不可恢复、Result 可恢复、? 向上传播
  • panic 交给程序 · Result 交给调用方? 交给上一层。：连到 Option、连到 From trait、连到测试

容易踩的坑

  • 注意expected 只匹配崩溃信息里的一段子串，写太具体。
  • 别拿它代替 Result。
  • 别处理成功和失败，编译器会强制你考虑失败分支。
  • 别常见，本质是把 ? 当成了自动包装返回值的东西，其实它只负责失败那条路径。

随堂练习

答案讲解：因为 ? 只是把错误提前返回、成功时取出值，并不会替你把值包成 Ok。函数签名声明要返回 Result，最后却给了一个裸 String，类型对不上，报 E0308。补一句 Ok(s) 就行。这个错特别常见，本质是把 ? 当成了自动包装返回值的东西，其实它只负责失败那条路径。

P12 · 泛型与 trait

第 10 章（上） · 视频 7.93 分钟 · ep12.mp4

本集目标

  1. 会读 trait bound —— 看懂 T: PartialOrd + Copy、where 子句和 E0277 的点名
  2. 把泛型用在类型和方法上 —— 分清类型参数、impl 参数与方法自己的参数
  3. 理解抽象为何零成本 —— 单态化生成专用代码，孤儿规则保证实现不冲突

核心规则

  • 加号读作「且」 —— 两个约束要同时满足，不是二选一。
  • Copy 为了按值取出 —— list[0] 与 for &item 都要求 T 能复制。
  • 换成 &T 或 Clone —— 绕开 Copy，就能支持 String 这类类型。
  • 报错会点名 —— E0277 直接告诉你哪个 trait bound 没满足。
  • 只描述「能做什么」 —— 方法可只有签名，也可带默认方法体。
  • Self 指实现类型 —— &self、-> Self 里的 Self 是当前类型。
  • 默认实现可覆盖 —— 不写用默认，写了以你的为准。
  • trait 能当约束 —— T: Summary 告诉编译器 T 上有哪些方法。

关键结论

  • 编译期各生成一份专用代码= 抽象不带来运行时开销：无虚表查找、可内联优化、零成本抽象
  • trait 与类型至少一个得是本地定义的。：本地类型 + 外部 trait、本地 trait + 外部类型、两个都外部则拒绝
  • 泛型给灵活性，trait 给约束，编译器把两者一起变成专用代码。：单态化、孤儿规则、where 子句
  • 泛型给灵活性 · trait 给约束编译器把两者变成专用代码。：连到单态化、连到迭代器、连到生命周期

容易踩的坑

  • 别只看定义，把同一个函数喂给两种类型试试。
  • 注意它写在函数或方法名后面，不是类型名后面。
  • 别喂给 i32 和 &str，编译器在编译期生成两份专用函数，运行时没有类型判断、也没有虚表查找。

随堂练习

P13 · 生命周期

第 10 章（下） · 视频 8.87 分钟 · ep13.mp4

本集目标

  1. 复现并读懂生命周期报错 —— 能用最小例子触发悬垂引用，靠错误码定位原因
  2. 分清标注与真实存活期 —— 明白标注只描述关系，不延长任何变量的寿命
  3. 写出带引用的函数与结构体 —— 掌握省略规则、impl 声明和静态引用的正确用法

核心规则

  • 每个引用参数获得各自的生命周期参数 —— fn foo(x: &str, y: &str) 相当于两个不同的标记
  • 只有一个输入生命周期 → 赋给所有输出 —— 所以 fn first_word(s: &str) -> &str 不用写标注
  • 方法里有 &self → 输出取 self 的生命周期 —— 这也是方法返回值常见的推断依据
  • 规则一 · 每个引用参数各得一个 —— 两个切片参数先变成各自独立的标记，互不干扰。
  • 规则二 · 只有一个输入就给所有输出 —— first_word 这类函数因此不用写任何标注。
  • 规则三 · 方法里有 self 就优先 —— 输出全绑到 self，哪怕还带着别的引用参数。
  • 填不满才报 E0106 —— 输出该绑谁有歧义时，编译器请你显式写出来。

关键结论

  • 两个标记只是名字约束看调用点的作用域：标注不改变存活期、输出绑谁要写清、省略规则兜底
  • 生命周期标注 = 给编译器的说明书不是延长寿命的魔法。：描述关系、约束返回范围、由作用域决定存活

容易踩的坑

  • 容易错在见报错就补标注，可悬垂引用是数据归属问题，加标记也救不回来。
  • 别急着改，先把代码缩到能复现的三五行，再用 rustc --explain 查说明。
  • 容易错在以为标注能延长局部变量的寿命，或者以为结果借的是外面那个就没事。
  • 容易错在反过来推，以为这段代码会报错，或在真正冲突时没意识到后面还有一次使用。
  • 容易错在把名字当成某种时钟，以为写长一点引用就活得久；真正决定存活期的始终是值所在的作用域和所有权。

随堂练习

答案讲解：不能。标注只描述引用之间的关系，不改变值的作用域。局部变量在函数返回时就被释放，标什么都救不回悬垂引用。正解是返回 String 交出所有权；用 leak 硬造静态引用只会泄漏内存。

  1. 标注是约束不是指令（P13）—— 标记描述输出与输入的关系，不改变作用域决定的存活期。
  2. 悬垂引用编译期被挡（P04）—— 呼应第 4 章所有权与借用，是内存安全承诺的落点。
  3. 静态引用与线程约束（P16）—— 为第 16 章用 Arc 共享数据埋下伏笔。

关键结论

P19 · 线程、消息与共享状态

第 16 章 无畏并发 · 视频 8.30 分钟 · ep19.mp4

本集目标

  1. 看懂编译期挡住了什么 —— 用 Rc 跨线程、两次可变借用的报错建立直觉
  2. 掌握两种动手写法 —— thread::scope 借用、Arc 共享与中毒恢复
  3. 把 Send/Sync 讲准 —— 知道它是 unsafe 自动派生的标记 trait，不是普通接口

核心规则

  • move 搬的是所有权 —— 把用到的变量移进闭包，原位置之后不能再碰。
  • Copy 类型走复制 —— i32、&T 这类按位复制，堆上的 String 则是真移动。
  • 'static 约束捕获 —— 要求闭包不持有指向当前栈帧的临时引用，不等于全局存活。
  • 整体还得 Send —— 捕获的所有东西都得可跨线程转移，否则照样被 E0277 拦下。
  • 加锁顺序不一致 —— 两线程各持一把锁互等，死锁；统一顺序或一次性锁多把。
  • 守护活得太长 —— MutexGuard 跨 .await / 做 I/O，会长期占锁并让 future 不 Send。
  • 临界区只放必要代码 —— 取出值就 drop 守护，耗时逻辑挪到锁外再算。
  • try_lock 探一探 —— 拿不到立刻返回，避免无限等待，也便于打破死锁。

关键结论

  • Send 管转移 · Sync 管共享unsafe 自动派生：无方法的标记 trait、编译器按字段推导、手写要 unsafe impl
  • channel 不共享 · Mutex 加锁= 数据竞争编译不过：move 转移所有权、Arc 原子计数、Send / Sync 背书

容易踩的坑

  • 别讲道理，看编译器怎么拦。
  • 容易错在忘了它会阻塞到全部线程收尾。
  • 容易错在拿它同步别的数据，得换 Ordering。
  • 别的数据，得换 Ordering。
  • 注意Send/Sync 是编译器自动派生的 unsafe 标记 trait，不是手动实现的普通接口。

随堂练习

提示：想想 spawn 闭包上的 Send 约束，以及 Rc 的计数为什么不安全。

答案讲解：因为 spawn 要求闭包满足 Send，而 Rc 的引用计数不是原子操作，被标记为 !Send，编译器用 E0277 拒绝。换成 Arc 就行，它的计数是原子的；若还要改里面的值，再套一层 Mutex。注意 Send/Sync 是编译器自动派生的 unsafe 标记 trait，不是手动实现的普通接口。

知识地图

  1. 编译期挡住数据竞争（P19）—— 所有权与借用规则从单线程延伸到多线程，是第 16 章的地基
  2. 消息传递与共享状态（P19–P20）—— channel 与 Mutex 两条路，最终都靠 Send / Sync 背书
  3. Send / Sync 的真身（贯穿全程）—— unsafe 自动派生的标记 trait，异步与线程池还会反复用到

P20 · async、await 与 Future

第 17 章 异步编程 · 视频 8.15 分钟 · ep20.mp4

本集目标

  1. 跑通异步的最小环境 —— 会配 Cargo.toml 依赖、读懂 #[tokio::main] 在做什么
  2. 亲手验证 future 惰性 —— 用最小 block_on 执行器证明不推进就一步不走
  3. 避开高频异步坑 —— 取消安全、锁跨 await、Pin 与 !Unpin 分别怎么处理

核心规则

  • 调用 = 只构造 —— async fn 调用返回一个状态机值，函数体一行未跑。
  • 推进靠 poll —— 执行器反复调用 Future::poll，遇到 Pending 就先去忙别的。
  • await 是让出点 —— 在 .await 处把控制权交回运行时，就绪后再回来续跑。
  • 别靠副作用计时 —— 没被推进的 future 里任何 println!、计数都不会发生。

关键结论

  • 线程跑运行时 · 运行时调度任务任务里再组合 多个 future：future 惰性、await 让出执行权、CPU 密集别放进 async
  • async 造 future · await 让出运行时负责推进：Future / Stream、join! 并发、tokio 提供调度

容易踩的坑

  • 别以为它只是语法糖，它决定了由谁驱动。
  • 别把它当普通结果用。
  • 注意await 只是挂起点，真正驱动它的是 #[tokio::main] 建的运行时。
  • 容易错在默认它总会执行到底，把不可重入的状态留在半路。
  • 别塞进 async 函数里。

随堂练习

答案讲解：不会。async fn 只是构造一个实现 Future 的状态机，函数体要等被 poll 才执行，这就是惰性。得在 async 上下文里 .await，或交给 tokio 这类运行时调度；单看返回值它一步都没动。想验证，调用后不 await 直接返回，再手写 block_on 循环 poll，输出就出来了。

知识地图

  1. async / await 的本质（P20）—— async fn 返回 impl Future，await 是让出点，连回第 17 章
  2. 执行器与惰性（P20–P22）—— 标准库只定义 Future 接口，推进工作交给运行时
  3. 并发与取消（贯穿全程）—— join! / select! 与取消安全，是写高并发服务的日常

P21 · 面向对象与模式语法

第 18–19 章 · 视频 8.23 分钟 · ep21.mp4

本集目标

  1. 说准 dyn 兼容 —— 能复现 E0038 并用 where Self: Sized 拆掉不兼容方法
  2. 把状态编码进类型 —— 用私有构造与 PhantomData 让非法状态构造不出来
  3. 补齐模式语法 —— 可反驳性、let-else、@ 绑定与 2024 版 let 链

核心规则

  • 方法返回值不能是 Self —— 运行时不知道 Self 到底是哪个具体类型
  • 方法不能带泛型类型参数 —— 单态化会为每种类型生成一份，和动态分发冲突
  • trait 不能要求 Self: Sized —— 要求固定大小与 dyn 的动态大小互相矛盾
  • 方法不能带泛型类型参数 —— 虚表编译期固定；换成关联类型或把方法拆到子 trait。
  • 方法不能返回 Self —— 运行时不知道具体类型；改返回 Box&lt;dyn Trait&gt;。
  • trait 不能要求 Self: Sized —— 与 dyn 的动态大小矛盾；给方法加 where Self: Sized 排除它。
  • 关联常量 / 泛型关联 —— 同样无法进虚表，只能留在具体类型上。
  • 匹配引用时绑定是引用 —— 对 &Point 解构，x 是 &i32，守卫里要写 *x，别当 i32 用。

关键结论

  • 状态编码进类型非法转移根本不存在：字段必须私有、状态多会类型爆炸、转换按值消耗 self
  • dyn 擦掉类型 · 模式拆开数据= 两种不同方向的抽象：对象安全、可反驳性、@ 绑定 + 守卫

容易踩的坑

  • 别急着删，对照错误码一条条验证最有收获。
  • 容易错在为了省事把字段全设 pub，封装当场失效，以后改内部表示处处受制。
  • 容易错在一律用泛型，等到要把不同类型装进同一个 Vec 才发现装不下。
  • 注意要 Rust 1.88 之后的 2024 Edition，旧工具链报 E0658；matches! 只判真假。
  • 注意守卫只是附加判断，不改变 match 的穷尽性检查，末尾那个兜底分支还是得留着，否则编译器会报没覆盖全。

随堂练习

题目：给 trait 加一个带泛型参数的方法后，Box 突然编译不过，报 E0038，怎么救？

答案讲解：这是 dyn 兼容被破坏：虚表编译期固定，泛型方法会为每种 T 生成一份，等于无穷多张表。救法是给该方法加 where Self: Sized 把它排除出虚表，只留给具体类型调用；或把泛型参数改成关联类型。别急着删 dyn，先想这方法是否真要动态调用。

P22 · 高级特性与最终项目

第 20–21 章 · 视频 8.33 分钟 · ep22.mp4

本集目标

  1. 说清 unsafe 的边界 —— 能证明它不关闭借用检查，并写出带 # Safety 的安全包装
  2. 跑通最终项目 —— 会用 channel + Arc 分发任务、用 Drop 优雅停机
  3. 把全书连成一条线 —— 从所有权到线程池，理解编译器一直在做同一件事

核心规则

  • ① 解引用裸指针 —— *const T / *mut T，可能为空、悬垂或别名冲突。
  • ② 调用 unsafe 函数 —— 前置条件写在签名上，调用处必须显式 unsafe。
  • ③ 访问可变静态变量 —— 全局可变状态的数据竞争要自己防。
  • ④ 实现 unsafe trait / ⑤ 读 union 字段 —— 前者向编译器担保，后者字段解释由你负责。
  • 借用检查并未关闭 —— unsafe 块里两个 &mut 依旧 E0499，别当万能开关。
  • FnOnce —— 任务只执行一次，执行后闭包本身被消耗。
  • Send —— 要经 channel 从主线程转移到 worker 线程。
  • 'static —— 不能借用栈上短命数据，捕获的东西得自己拥有。

关键结论

  • 所有权是根 · trait 是抽象编译器是你最较真的搭档：22 集覆盖 21 章、从 Hello World 到线程池、报错是设计说明

容易踩的坑

  • 别和主程序混在一起。
  • 别名用 type 给长类型起短名。
  • 容易错在把 ! 当成能存进变量的普通类型，它没有值；Infallible 是没变体的枚举，也别混。
  • 别名只是同义简写，不新建类型，别指望它挡住把米当公里传；newtype 才是真新类型，还能绕开孤儿规则给外部类型实现 tr。
  • 别的函数；闭包要返回出去，得用 Box 包一层。
