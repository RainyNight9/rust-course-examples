## 镜 03 · 一条命令装好工具链（P02 00:50）

归类：命令行示例。

> rustup 还能切换 stable / beta / nightly，以及用 rustup doc 打开本地离线文档。

```bash
$ curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
$ rustc --version
rustc 1.98.0
$ cargo --version
cargo 1.98.0
```

## 镜 05 · channel 用三条命令管住（P02 01:25）

归类：命令行示例。

> cargo +nightly 只对这一条命令切换工具链，不改全局默认。

```bash
$ rustup show
$ rustup update stable
$ rustup toolchain install nightly
$ cargo +nightly build
$ rustup doc --std
```

## 镜 10 · rustc 直编的完整命令（P02 02:47）

归类：命令行示例。

> 省略 --edition 时按 2015 处理，这是手动编译最常踩的坑。

```bash
$ rustc main.rs --edition 2024 -o hello
$ ./hello

```

## 镜 14 · 锁文件由 Cargo 自动维护（P02 03:59）

归类：命令行示例。

> 改依赖版本请改 Cargo.toml 再 cargo update，别手改 lock。

```bash
$ cargo new demo && cd demo
$ ls            # 此时还没有 Cargo.lock
$ cargo build   # 第一次构建后生成 Cargo.lock
$ cargo update  # 按清单规则刷新精确版本
```

## 镜 17 · 用 cargo tree 查依赖树（P02 04:52）

归类：命令行示例。

> cargo tree 只读依赖图、不改任何文件，排查版本问题先跑它。

```bash
$ cargo tree
$ cargo tree -d        # 找出重复版本
$ cargo tree -i rand   # 反查谁依赖了 rand
```

## 镜 18 · 六个命令覆盖日常开发（P02 05:11）

归类：命令行示例。

> 先把 cargo check 用熟，能省掉大量等待编译的时间。

```bash
$ cargo new hello_cargo
$ cargo check        # 只检查，最快
$ cargo build        # 编译，产出 target/debug/
$ cargo run          # 编译 + 运行
$ cargo test         # 跑测试
$ cargo fmt && cargo clippy
```
