# 引用、借用与生命周期 —— 用一个值，而不交出它

## 导语

P05 留下一个实际问题：函数只想读一下某个值，却得把所有权交出去、再靠返回值接回来。P06《引用、借用与 slice》与 P13《生命周期》共同补上所有权模型的另一半：前者给出「借用」这一使用权，后者给出编译器确认引用有效的标注。这两处同样是分水岭——此后写函数签名、设计结构体字段、判断代码能否并发，都要回到借用规则与引用有效期上。P06 对应第 4 章「所有权（下）」，关键节点 03:46 记牢两条规则、04:01 与 04:22 复现 E0499、E0502；P13 对应第 10 章（下），关键节点 00:52 返回局部变量失败、04:32 省略规则、05:22 的 impl 声明。

## 一、引用：不取得所有权的使用权

取地址符 & 创建引用，星号 * 解引用；引用只存原数据的地址，不持有堆内存，因此离开作用域不会释放所指数据，这一动作叫借用。函数签名与实参的取地址符必须成对：参数写 &String、调用传 &s，函数结束只是借用结束，原值从未离开调用方，也不必用元组接回来。

> 文件：`ch06/examples/p06_s04.rs` · 运行：`cargo run -p ch06 --example p06_s04`

```rust
fn calculate_length(s: &String) -> usize {
    s.len()
} // s 是引用，不拥有值，这里不会 drop 数据

fn main() {
    let s = String::from("hello");
    let n = calculate_length(&s);
    println!("{s} 有 {n} 个字节");   // s 仍可用
}
```

对引用调用方法时，Rust 会自动解引用与再借用，不必写成 (*s).len()（`p06_s07.rs`）。借用区间也不死板到花括号结束：编译器用非词法生命周期（NLL）判断，从创建引用算到最后一次使用为止。字符串切片 &str 也是不持有所有权的引用；参数写成 &str 比 &String 更通用，字符串引用、字面量、切片都能传入（`p06_s21.rs`）。

## 二、两条借用规则与几个高频错误码

规则只有两条：同一时刻要么只有一个可变引用，要么有多个不可变引用，二者不可兼得；引用必须总是有效。它们与线程无关，单线程同样检查。

想通过引用修改数据，变量声明、实参 &mut、形参 &mut 三处都要写 mut，缺一处报 E0596（`p06_s10.rs`）。同一作用域先后拿两个可变引用、且第一个后面还在用，报 E0499（`p06_s13.rs`）；只读引用尚在存活区间又取可变引用去改，报 E0502（`p06_s14.rs`），即随堂练习：先拿首元素的不可变引用，再追加，最后打印该引用。

> 反例：`compile-fail/p06_s14.rs` · 复现 E0502：`rustc compile-fail/p06_s14.rs`

```rust
fn main() {
    let mut v = vec![1, 2, 3];
    let first = &v[0];
    v.push(4);
    println!("{first}");
}
```

数据竞争需三个条件同时成立：多指针访问同一数据、至少一个在写、没有同步；借用规则把后两条判为非法，把这类 bug 挡在编译期。让只读借用先用完再改，区间不重叠即可通过。

> 文件：`ch13/examples/p13_s09.rs` · 运行：`cargo run -p ch13 --example p13_s09`

```rust
fn main() {
    let mut v = vec![1, 2, 3];
    let first = &v[0];
    println!("{first}");   // 最后一次使用
    v.push(4);             // 此处借用已经结束，合法
}
```

## 三、悬垂引用：先问数据归谁

函数内部创建的 String 若以引用返回会被拒绝：函数一结束值就释放，引用立刻指向已释放内存。`p06_s18.rs` 报 E0106，`p13_s03.rs` 报 E0515，指向同一件事。正解不是补标注，而是换数据归属：返回 String 交出所有权，或返回字面量 &'static str（`p13_s13.rs`）；用 leak 硬造静态引用只会泄漏内存。

这也点明标注的定位：它不是续命的魔法，只描述引用之间的关系，据此检查有没有引用比数据活得长。`&'a str` 里的 'a 只是标签，惯例用 a、b、c，既不创建也不延长生命周期。

## 四、标注、省略规则与结构体里的引用

编译器内置三条省略规则，能推断时就不必手写：每个引用参数各得一个生命周期；只有一个输入时赋给所有输出；方法里有 &self 时输出取 self 的生命周期。三条都填不满、输出该绑谁有歧义时才报 E0106，例如 `fn longest(x: &str, y: &str) -> &str`（`p13_s05.rs`）。

> 文件：`ch13/examples/p13_s06.rs` · 运行：`cargo run -p ch13 --example p13_s06`

```rust
fn first<'a>(x: &'a str, y: &str) -> &'a str {
    let _ = y;
    x
}

fn main() {
    let s = String::from("hello world");
    let word = first(&s, "unused");
    println!("{word}");
}
```

这里输出显式绑定 x，y 交给省略规则；若把所有参数都标成同一个 'a，约束过紧，本该通过的调用反而被拒。两个输入标同一标记时取较短的作用域，内层字符串先离开花括号，结果却想活到后面的打印，便报 E0597（`p13_s07.rs`）。'b: 'a 读作 b 至少和 a 一样久（`p13_s14.rs`）。

结构体字段若持有引用，就必须标生命周期，因为实例不能比它引用的数据活得更久（`p13_s17.rs`）；给这样的结构体写方法，得先在 impl 后声明标记，漏掉报 E0261（`p13_s18.rs`）。字段改用 String 则不必标注——实例自己拥有数据。'static 表示引用在整个程序运行期有效，字面量天然如此；局部引用硬标成 'static 不被接受（`p13_s21.rs`）。复杂签名里泛型、trait bound 与生命周期参数可同时出现，生命周期在前（`p13_s22.rs`）。

## 常见坑

- 签名忘了写取地址符，结果仍按值传参、移走所有权；或在需要所有权处误传引用。
- 以为必须用花括号缩短借用作用域。NLL 看的是最后一次使用点，区间不重叠即可通过。
- 一看到缺标注就补标记。悬垂引用是数据归属问题，加标记救不回来；应先缩到能复现的三五行，再用 rustc --explain 读原因。
- 以为标注能延长局部变量的寿命，或把 'static 当万能补丁。决定存活期的始终是作用域与所有权。
- 切片落在 UTF-8 多字节字符中间会运行时 panic，中文尤其容易踩；要么按字符边界切，要么用 get 兜底。
- 把所有引用参数标成同一个 'a，约束过紧，本该通过的调用反而被拒。

## 小结

三条所有权规则加两条借用规则构成第 4 章的骨架，生命周期则把「引用必须有效」写成可检查的约束：标注描述关系，省略规则兜底，存活期始终由作用域与所有权决定。建议把两道随堂练习复述并复现——先拿首元素不可变引用再追加为何报 E0502、给返回局部变量引用的函数加标注能否通过——再用 cargo check 观察加标注前后的变化。配合 B 站《Rust 程序设计语言》22 集视频合集与本仓库配套代码继续阅读，后续结构体、智能指针与无畏并发章节都会回到这一框架。
