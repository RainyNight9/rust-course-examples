# P17 · 发布、文档与工作空间 — 讲解摘录

对应 第 14 章 Cargo 进阶。以下片段按视频顺序保留原样，
它们是命令行、配置、控制台输出、第三方依赖示例或教学语句摘录，**不是可独立编译的程序**。

## 镜 04 · profile 决定哪一档（P17 01:10）

归类：命令行示例。

> --release 选用 release profile，其余默认走 dev。

```bash
$ cargo build              # target/debug
$ cargo build --release    # target/release
$ cargo test --release     # 发布档下跑测试
$ cargo doc --no-deps --open
```

## 镜 05 · 两套构建配置（P17 01:31）

归类：配置 / 输出片段。

> lto 打开链接期优化、codegen-units = 1 换更好的优化，代价都是编译更慢。

```toml
[profile.dev]
opt-level = 0

[profile.release]
opt-level = 3
lto = true
codegen-units = 1
```

## 镜 06 · dev 也能单独调（P17 01:47）

归类：配置 / 输出片段。

> 只覆写写出的项；lto 与 codegen-units 换优化但拖慢编译。

```toml
[profile.dev]
opt-level = 1
debug = true

[profile.release]
opt-level = 3
lto = "thin"
codegen-units = 1
panic = "abort"
overflow-checks = false
```

## 镜 07 · 用 inherits 继承（P17 02:06）

归类：配置 / 输出片段。

> 自定义 profile 必须写明 inherits，产物在 target 下同名目录。

```toml
[profile.profiling]
inherits = "release"
debug = true

[profile.bench]
inherits = "release"
lto = true

$ cargo build --profile profiling
```

## 镜 11 · pub use 重导出（P17 03:18）

归类：配置 / 输出片段。

> 重导出不改变内部结构，只是换一个更友好的对外门牌号。

```toml
// src/lib.rs
pub mod kinds;
pub mod utils;
pub use self::kinds::PrimaryColor;
pub use self::utils::mix;

// 用户侧
use art::PrimaryColor;   // 不用写 art::kinds::PrimaryColor
```

## 镜 13 · 发布前先预演（P17 03:50）

归类：命令行示例。

> --dry-run 能提前发现漏文件、缺元数据这类问题。

```bash
$ cargo package --list
$ cargo publish --dry-run
$ cargo package --allow-dirty
```

## 镜 15 · 发布前补全字段（P17 04:24）

归类：配置 / 输出片段。

> keywords 最多五个；categories 要用官方分类。

```toml
[package]
name = "my_crate"
version = "0.1.0"
edition = "2024"
description = "一句话说清这个库做什么"
license = "MIT OR Apache-2.0"
readme = "README.md"
keywords = ["cli", "text"]
categories = ["command-line-utilities"]
```

## 镜 17 · 一个仓库多个包（P17 05:07）

归类：命令行示例。

> 工作空间内互相依赖用路径依赖：add_one = { path = "../add_one" }。

```bash
# 根目录 Cargo.toml
[workspace]
members = ["adder", "add_one", "cli"]
resolver = "2"

$ cargo build                  # 全部
$ cargo test -p add_one        # 只测某个包
```

## 镜 18 · cargo install 与自定义子命令（P17 05:19）

归类：命令行示例。

> 这是 Cargo 的扩展机制，社区工具常以 cargo-xxx 命名发布。

```bash
$ cargo install ripgrep
$ cargo install cargo-edit
$ cargo add serde          # 由 cargo-edit 提供

$ cargo --list             # 查看所有可用子命令
```

## 镜 19 · 只写一次版本（P17 05:32）

归类：配置 / 输出片段。

> resolver = "2" 是 2021 起推荐的解析策略。

```toml
[workspace]
members = ["adder", "cli"]
resolver = "2"

[workspace.dependencies]
serde = "1"
anyhow = "1"

# 成员清单里：
# [dependencies]
# serde = { workspace = true }
```

## 镜 21 · 发布出去就收不回（P17 06:12）

归类：命令行示例。

> --dry-run 能提前发现漏文件、缺元数据这类问题。

```bash
$ cargo test
$ cargo publish --dry-run    # 本地预演打包
$ cargo publish
$ cargo yank --vers 1.0.1    # 撤回（不删除）
```
