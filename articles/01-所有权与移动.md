# 所有权与移动 —— 把内存管理的判断挪到编译期

## 导语

在《Rust 程序设计语言》22 集中文系统课里，P05《所有权与移动》是公认的分水岭。此前变量、类型与控制流的写法与其他语言相差有限；从第 4 章起，编译器开始介入每一次赋值与传参，凭直觉写下的代码会第一次编译不过。Rust 既无垃圾回收器，也不要求手写 free，而是把「谁负责释放」交给一组编译期检查的规则。理解它，后面的引用、生命周期、智能指针与并发安全才有共同底座。P05 对应第 4 章「所有权（上）」，视频约 8.85 分钟，关键节点在 04:25 复现 E0382、06:18 讨论函数传参、06:55 对照 Copy 与 Move。

## 一、第三条路：资源跟着作用域走

内存管理有两条老路：垃圾回收把存活对象的维护放在运行时，省心但可能停顿；手动管理把分配与释放成对写进代码，快却容易泄漏、悬垂、二次释放。Rust 选第三条：把判断挪到编译期，违反规则便编译不过。开发者从不写释放代码，只需讲清谁拥有这份数据。

要懂规则，先分清栈与堆。栈放编译期大小已知的值，存取快；堆放大小会变的数据，访问要过一层指针。一个 String 在栈上只有三个机器字：指向堆缓冲的指针、已用长度、已申请容量，字节在堆上。所有权系统操心的正是堆数据。资源随作用域走，这套机制在 C++ 里叫 RAII：获取即初始化，离开作用域由析构释放。字符串在内层右花括号处自动 drop，文件、锁、连接同理。`p05_s12.rs` 里内层块结束释放 inner，outer 要等外层结束才释放，顺序与创建相反；编译器还看最后一次使用位置，让借用提前结束。

> 文件：`ch05/examples/p05_s12.rs` · 运行：`cargo run -p ch05 --example p05_s12`

```rust
fn main() {
    let outer = String::from("out");
    {
        let inner = String::from("in");
        println!("{inner}");
    } // inner 在这里 drop
    println!("{outer}");
} // outer 在这里 drop
```

## 二、三条规则，以及「移动」到底移动了什么

整套系统可收敛成三句话：每个值都有一个所有者；同一时刻有且只有一个所有者；所有者离开作用域，值就被丢弃。它们不是条文，而是能推出所有现象的公理：既然不允许两个变量同时拥有同一份堆数据，赋值就必须让旧的失效；既然离开作用域就释放，函数结束自然会清理它拥有的值。

因此 `let s2 = s1;` 不复制堆内容，只复制栈上那三个字段。若两份元数据指向同一块堆，离开作用域会二次释放。Rust 的处理很干脆：赋值后让 s1 失效，这个动作叫移动。移动后再用原变量报 E0382，报错还会标出值在哪句被移动，并建议 clone 或借用。

> 反例：`compile-fail/p05_s16.rs` · 复现 E0382：`rustc compile-fail/p05_s16.rs`

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;
    println!("{s1}, world!");
}
```

移动也不限于整个变量赋值：单独取走结构体的某个 String 字段，该字段即被移走，此后结构体不能整体使用（`p05_s17.rs`，同为 E0382），`p05_s15.rs` 是最精简的三行复现。后面借用报错沿用同一套格式，学会顺着「在哪移动」往下读即可。

## 三、clone 与 Copy：把开销写在明处

既然默认只做便宜的栈上复制，为何不每次赋值都把堆内容拷一份？那样一次普通赋值就会悄悄变成分配加整段拷贝，开销无法预期，两份元数据还会指向同一块堆。Rust 把选择权交还写代码的人：真要深拷贝就显式写 clone，看到它即知有分配成本。

> 文件：`ch05/examples/p05_s08.rs` · 运行：`cargo run -p ch05 --example p05_s08`

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone();   // 显式深拷贝堆数据
    println!("s1 = {s1}, s2 = {s2}");
}
```

另一类值不需要这套判断。整数、浮点、布尔、字符，以及只含 Copy 元素的元组与定长数组，编译期大小已知、整个在栈上，赋值按位复制，原变量照常可用。判断标准只有一条：类型是否实现 Copy trait。可变引用不是 Copy；而实现了 Drop、需要自定义清理逻辑的类型（例如 String）绝不能再实现 Copy，否则按位复制出的两份会在释放时归还同一块内存两次。

## 四、函数传参：传进去，还得还回来

把值传给函数和赋值遵循同一套规则：堆数据被移动，Copy 类型被复制。调用 `takes_ownership(s)` 后 s 便不可用；想继续使用，只能让函数把值作为返回值交回来，返回值同样把所有权移给调用方（`p05_s21.rs`、`p05_s22.rs`）。于是出现别扭的写法：函数只想算个长度，却得用元组把原字符串原样带回来。`p05_s23.rs` 把两类值摆在一起对照，差异完全由类型是否实现 Copy 决定，不看变量名。这种「每次都要还回来」的麻烦，正是 P06 引用与借用要补的缺口。

> 文件：`ch05/examples/p05_s23.rs` · 运行：`cargo run -p ch05 --example p05_s23`

```rust
fn takes_int(x: i32) { println!("{x}"); }
fn takes_str(s: String) { println!("{s}"); }

fn main() {
    let x = 5;
    takes_int(x);
    println!("{x}");            // OK：i32 是 Copy
    let s = String::from("hi");
    takes_str(s);
    // println!("{s}");         // 报错：String 已移动
}
```

## 常见坑

- 以为没有 GC 就得手动释放。开发者从不写释放代码，只需讲清谁拥有；靠 mem::forget 跳过 drop 通常意味着泄漏。
- 以为赋值就是拷贝。String 赋值是移动，两个变量指向同一块堆会二次释放，故 s1 立即失效。
- 一见 E0382 就加 clone。应先读报错标出的移动位置，判断能否改用借用，避免掩盖接口设计问题。
- 以为所有赋值都让原变量失效。判断标准只有一条：是否实现 Copy；不可变引用是 Copy，可变引用不是。
- 把内部块的临时值拿到块外用。内层右花括号一到，值已 drop。
- 给需要自定义 Drop 的堆数据结构体顺手派生 Copy。类型系统禁止这种组合。

## 小结

P05 把栈与堆、三条所有权规则、作用域与 drop、移动语义，以及 clone 与 Copy 的分工串成一条线：一个值对应一个所有者，移动是「唯一所有者」的推论，clone 是把开销明写出来的例外。建议把随堂练习复述一遍——字符串赋值后为何报 E0382、为何不直接复制堆内容——再把上文示例亲手敲一次。配合 B 站《Rust 程序设计语言》22 集视频合集与本仓库配套代码继续阅读，下一篇《引用、借用与 slice》将回答怎样使用一个值又不交出所有权。
